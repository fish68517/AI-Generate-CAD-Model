# CADmium 本机轻量复现实施效果

> 实施日期：2026-08-12  
> 实施范围：数据抽样、轻量脚本、CPU 几何重建、结果可视化、低长度/量化推理试验  
> 未实施：论文规模 GPU 训练、完整 8,046 条测试集评价、PythonOCC 官方指标复现

## 1. 总体结论

本机轻量开发路线已经形成可重复运行的闭环：

```text
公开 CADmium-ds
→ 平衡抽取 20 条真实 test 样本
→ JSON/schema/token 审计
→ CPU JSON 重建
→ STL + PNG + 交互 HTML
→ CADmium-1.5B 本地 CPU 推理
→ 预测 JSON 重建
→ 真实/预测 mesh 对比
```

核心结果：

- 固定官方代码提交 `2b2a5e7346e17a239ffe6f4a932610bfdb9766c6`。
- 20 条真实测试 JSON 全部通过解析和 schema 基础检查。
- CPU 轻量重建 **20/20 成功，20/20 为 watertight mesh**。
- 每条样例均生成 STL、静态 PNG、交互式 HTML 和状态 JSON。
- CADmium-1.5B 基座和 LoRA adapter 已下载到本地并校验 SHA256。
- fp32 CPU 和 int8 CPU 均完成真实生成；int8 内存约为 fp32 的一半，但输出质量明显退化。
- 使用真实测试提示时，fp32 生成合法 JSON，且能重建为 watertight STL；但把目标矩形板误生成为圆盘，说明“可解析/可重建”不等于“几何正确”。
- GTX 1050 Ti 虽被驱动识别，但当前 PyTorch 是 CPU build，CUDA 4bit 路线未能执行；即便换 CUDA build，4GB 显存也不足以稳健承载该 1.5B 模型、LoRA、长上下文和 KV cache。

## 6. 低资源推理效果

### 6.1 推理链路修复

实施中处理了以下实际兼容问题：

1. adapter 自带 `tokenizer.json` 与当前 tokenizers 版本不兼容，改为加载对应 Qwen 基座 tokenizer；
2. adapter 配置包含新版 PEFT 字段，脚本按本机 `LoraConfig` 支持字段过滤；
3. 继承环境中的 protobuf 太旧，局部安装 `protobuf==5.29.6`；
4. 禁用无关 TensorFlow 加载；
5. 使用 `json.loads()` 而不是官方 Demo 中的 `eval()`；
6. 模型生成合法 JSON 后自动进入 CPU 重建并记录 S0–S5 状态。

### 6.2 fp32 与 int8 对比

对简短“0.75 × 0.5 × 0.2 矩形棱柱”提示：

| 模式 | 生成 | 速度 | 常驻内存 | JSON | 几何结果 |
|---|---:|---:|---:|---|---|
| CPU fp32，32 token | 32 tokens | 0.2809 token/s | 8,288.5MB | 不完整 | 未评价 |
| CPU int8，32 token | 32 tokens | 0.4001 token/s | 4,037.3MB | 不完整 | 未评价 |
| CPU int8，最长 384 | 实际 142 tokens | 1.5718 token/s | 4,085.1MB | 非法 JSON，含注释且 schema 错误 | 不可重建 |
| CPU fp32，最长 384 | 实际 248 tokens | 2.1565 token/s | 8,291.9MB | 合法 JSON | S3：拉伸深度为 0，不可重建 |

int8 将内存约从 8.3GB 降到 4.1GB，但本次输出质量更差。动态量化并不能保证这个 LoRA 模型维持结构化生成质量。

### 6.3 真实 test 提示闭环

样本 `0026/00267624` 的真实目标是 0.75 × 0.75 × 0.0375 的矩形薄板，并带指定旋转和平移。fp32 CPU 结果：

| 项目 | 结果 |
|---|---:|
| 输入 tokens | 829，无截断 |
| 生成 tokens | 252 |
| 生成耗时 | 115.985 秒 |
| 速度 | 2.1727 token/s |
| 常驻内存 | 8,444.8MB |
| JSON 解析 | 成功 |
| CPU 重建 | S5，成功 |
| Watertight | True |
| 预测形状 | 圆盘，而非矩形薄板 |
| CD ×1000 | 479.6519 |

GT 与预测都 watertight 且 Euler number 都为 2，但几何语义错误明显：模型使用 `circle_1`，没有生成矩形的四条直线；也没有遵循输入旋转和平移。因此本次只能证明 **模型链路可运行**，不能称为论文效果复现。

对比报告：[comparison.json](../reports/inference/sample_0026_00267624/comparison/comparison.json)；可视化：[comparison.png](../reports/inference/sample_0026_00267624/comparison/comparison.png)；交互模型：[interactive.html](../reports/inference/sample_0026_00267624/reconstruction/inference_cpu-fp32/interactive.html)。

## 8. 本轮效果的正确解读

本轮完成的是开发计划中的 R0，以及 R1 的“有限本地试验版”：

- R0 已完成：真实 JSON → CPU 几何 → STL/PNG/HTML 稳定闭环；
- R1 部分完成：官方 1.5B base + LoRA 能在 CPU 生成，合法 JSON 可重建；
- R1 尚未达到质量验收：单个真实提示生成几何错误，未运行足够样本统计；
- R2/R3 未开始：本机不适合 GPU LoRA 训练或论文规模实验。

下一阶段最有价值的工作不是在这台机器上训练，而是把当前已验证代码迁移到 24GB 以上 GPU：先用官方 1.5B adapter 批量推理 20 条，再做 1.5B 小样本 LoRA smoke test。届时应恢复 4,096 最大长度，并以当前 20 条样本作为固定回归集。
